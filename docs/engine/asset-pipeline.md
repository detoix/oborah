# Asset Pipeline

## Philosophy

The majority of 3D objects across all apps should be generated procedurally at runtime. Hand-modeled assets are exceptions, not the rule. Textures do the heavy lifting — a box with a good PBR wood texture is indistinguishable from a hand-modeled plank.

## Asset types

### 1. Procedural meshes (90% of all objects)
Defined in config.json as shape + dimensions + material. Generated by the engine at runtime.

**Supported shapes:**
- `box` — boards, panels, tiles, shelves, slabs, posts (square profile)
- `cylinder` — round posts, pipes, rails, bollards
- `extrusion` — L-shapes, U-channels, moldings, gutters (2D profile extruded along length)
- `lathe` — bowls, vases, turned legs (2D profile revolved)
- `plane` — ground overlays, decals, labels, flat surfaces

**Each shape supports:**
- Arbitrary dimensions
- Bevel / edge rounding (radiused edges look way more realistic)
- UV mapping mode: `stretch`, `tile` (repeat based on real-world scale), `auto`
- Material assignment from shared library

**No files to create, no files to manage.** The config file IS the model.

### 2. PBR texture sets (the real investment)
A texture set consists of:
- Diffuse / albedo map (color)
- Normal map (surface detail)
- Roughness map (shininess)
- Optional: AO (ambient occlusion), displacement

**Target library size:** 50-100 high-quality material sets covering:
- Woods: cedar, pine, oak, walnut, teak, bamboo, composite (grey/brown/black)
- Stones: granite, marble, slate, limestone, sandstone, bluestone, travertine
- Metals: brushed steel, matte black, brass, copper, aluminum, galvanized
- Concrete: smooth, brushed, stamped, exposed aggregate
- Brick: red, white, grey, clinker
- Tiles: ceramic white, subway, hexagonal, terracotta
- Fabric: canvas, linen (for furniture in room configurators)
- Paint: flat colors (10-20 standard colors, generated, not photographed)
- Grass/earth: lawn, soil, gravel, mulch, sand

**Sources:**
- Polyhaven (CC0, free) — primary source
- ambientCG (CC0, free) — supplementary
- Custom-made where needed (photograph + process in Materialize or similar)

**Format:** KTX2 compressed. ETC2 encoding for mobile, BC7 for desktop. The engine auto-selects based on device.

**Resolution:** 1024×1024 for most materials. 2048×2048 for hero materials (visible up close). Never higher — unnecessary for web.

### 3. GLB models (rare, hero objects only)
For objects too complex for procedural generation: furniture, appliances, fixtures, vehicles, decorative objects.

**Pipeline:**
1. Model in Blender (low-poly, max 5k triangles per object)
2. UV unwrap
3. Assign materials from the shared texture library (reuse, don't bake unique textures)
4. Export as GLB (binary glTF — smallest file format for web 3D)
5. Optimize with gltf-transform (Draco compression, texture compression)
6. Place in site's `/public/assets/` or in shared `/packages/assets/` if reusable

**Naming convention:** `[category]-[name].glb` — e.g., `furniture-eames-chair.glb`, `fixture-pendant-light.glb`

**Target file size:** Under 500KB per model. Under 200KB preferred.

### 4. HDR environment maps
For realistic lighting and reflections on metallic/glossy surfaces.

**Need:** 2-3 environment maps total:
- Outdoor daylight (for ground-plane configurators)
- Indoor neutral (for room configurators)
- Overcast (for visualizers)

**Source:** Polyhaven HDRIs (CC0, free)
**Format:** HDR or EXR, compressed to small resolution (256×128 is enough for ambient lighting)

## Asset reuse matrix

The power of the library is in reuse. Examples:

| Texture | Used in |
|---|---|
| cedar wood | deck, fence, pergola, garden bed, shelf, wainscoting |
| composite grey | deck, fence, balcony railing |
| subway tile | kitchen backsplash, bathroom wall, shower niche |
| brushed steel | desk setup, kitchen, railing, tool wall |
| concrete smooth | patio, driveway, garage floor, retaining wall |
| lawn grass | garden, yard (ground plane texture) |

By configurator #30-50, most new sites require zero new textures. The library is already complete for that category.

## Asset storage and delivery

**Storage:** Cloudflare R2 (S3-compatible, cheap, no egress fees)

**Structure on CDN:**
```
assets.designyour.app/
  textures/
    wood/
      cedar_diff_1k.ktx2
      cedar_nor_1k.ktx2
      cedar_rough_1k.ktx2
    stone/
    metal/
    ...
  models/
    furniture/
    fixtures/
    ...
  hdri/
    outdoor_daylight_256.hdr
    indoor_neutral_256.hdr
```

**Loading strategy:**
- Textures load lazily when a material is first selected
- Models load lazily when an object is first placed from catalog
- Ground plane / map loads immediately (perceived performance)
- Show low-res placeholder texture instantly, swap to full-res when loaded

## Quality checklist for new assets

- [ ] Texture resolution is 1024×1024 or 2048×2048
- [ ] KTX2 compressed with both ETC2 and BC7 variants
- [ ] GLB model is under 500KB and under 5k triangles
- [ ] UV tiling looks correct at real-world scale (1m = 1m, not stretched)
- [ ] Material looks correct under both outdoor and indoor HDRI lighting
- [ ] Asset is named according to convention
- [ ] Asset is registered in the material catalog (if texture) or model catalog (if GLB)
- [ ] Asset renders correctly on mobile (test on a real phone or throttled Chrome)

## For AI agents

When a new site needs assets:
1. First check the existing texture and model library — reuse wherever possible
2. If a new texture is needed, check Polyhaven and ambientCG first
3. Procedural shapes with existing textures should always be preferred over new GLB models
4. All textures must be KTX2 compressed before deployment
5. All GLBs must be Draco-compressed via gltf-transform
6. Never create assets larger than the quality checklist allows
